- [x] 5.1 **Spike resolved: go.** Renderer (`src/web/homeRangeRendererScript.ts`: Gaussian blur σ=1 cell, marching-squares 0.5-contour, Lab-interpolated wildness→colour LUT, `visits`→brightness, canvas → `L.imageOverlay`) confirmed on a real device — soft, rounded edges (not blocky/grid-like), plausible green fill. `fillAlpha` raised 0.28→0.6 after initial on-device testing found it too faint (see separate commit "Raise Home Range fill opacity for legibility"). Pan/zoom performance not separately stress-tested but no lag reported.
- [x] 5.2 Replace `SHOW_ALL_TERRITORIES`/`SHOW_TERRITORY` in `mapHTML.ts` with a single `SHOW_HOME_RANGE` message per Decision 6's bridge payload shape (`{ origin: [ix0, iy0], w, h, wild: base64(Uint8Array), visits: base64(Uint8Array) }`) — done, `MapView.tsx` now builds this via `homeRangeRepository.getCells()` + `buildHomeRangeRasterPayload`, replacing the old `walkRepository.getWalks()` + `territories.map(...)` flow entirely. **Simplification, not fully done as specified:** it fetches the *entire* persisted Range each refresh, not a viewport-scoped 2.5km window computed from the current map bounds, and does not downsample at wide zooms. `HomeRangeRepository.getCellsInBounds` (section 2.1) is implemented and available for this, just not wired to live pan/zoom tracking yet — true interactive viewport-following needs a WebView→RN bounds-report round trip this pass didn't build. `design.md`'s own Risks section calls the unbounded-Range case "not urgent" for now; flagging this as a real gap against the task's literal text, not silently claiming full completion.
- [x] 5.3 Live-walk painting preview: while a walk is in progress, `MapView.tsx` recomputes `paintedCells(locations)` on every `locations` change and overlays those cells (fully fresh) on top of the last-fetched persisted Range, entirely in memory — no DB write until Finish Walk (section 2.2's batch write is unchanged).
