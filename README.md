# Dog Territory Defender

Location-based mobile game for dog owners: walk → GPS trail → close loop → claim territory. Spring-like, joyful, cookie-clicker background loop. Spec-driven — see `openspec/` for build plan and game design.

## Setup

### Prerequisites
- Node.js 16+
- Android phone (API 26+), same WiFi as your computer (or USB debug)
- Android SDK + connected device/emulator (`adb devices`)

### Run

```bash
npm install
npx expo run:android   # builds + installs dev client (Expo Go alone isn't enough)
```

**Why not Expo Go:** background GPS tracking needs native config (foreground service, background-location entitlement) that only takes effect in a real native build. Re-run `npx expo run:android` when native config changes — day-to-day JS changes hot-reload without a rebuild.

The earned-trigger notification (Den-economy overflow) added `expo-notifications` as a new native dependency — after pulling that change, run `npx expo install expo-notifications` (not a plain `npm install`; `expo install` resolves the SDK-54-compatible version) and rebuild the dev client (`npx expo run:android` / `run:ios`) before the notification permission prompt or delivery can be tested on-device. It's requested lazily (only when an overflow actually needs to be surfaced), not at app launch.

The opt-in walk reminder (`openspec/changes/walk-reminder`) added `@react-native-community/datetimepicker` as a second new native dependency, for the player's own real time picker in Settings — after pulling that change, run `npx expo install @react-native-community/datetimepicker` and rebuild the dev client the same way before the Settings screen's time picker can be tested on-device.

Testing without walking: Android Emulator → Extended Controls → Location → Routes, import a GPX route from `testing/`.

### Release APK

`npm run apk` builds `android/app/build/outputs/apk/release/app-release.apk` (debug-keystore signed, personal use only). For a cloud-built APK: `npx eas build -p android --profile preview`. The icon and splash are native, so changing them needs a native rebuild (`npx expo prebuild --platform android`, then rebuild). Dev client workflow for day-to-day work: `npx expo start --dev-client`.

## Architecture

React Native / Expo app, no backend yet — everything runs and persists locally.

- **Map & GPS**: a WebView-hosted Leaflet map tracks and renders the live GPS trail, plus the player's persistent Home Range (see below); a foreground location service keeps tracking accurate while backgrounded.
- **Walk lifecycle**: a walk starts, accumulates GPS points, and ends via one of two terminal actions — Finish Walk (always saves the trail and paints it into the Home Range, regardless of shape) or Cancel (discards the walk entirely). There is no loop-closure requirement anymore: a walk that never returns near its start still paints exactly like one that does. Reward eligibility (treats/XP) is gated on ground actually covered — at least 25 painted 20m grid cells, roughly 200m of real walking — not on the walk's shape; a shorter walk still saves and still paints, it just earns nothing. A third way a `Walk` comes to exist: "Log a walk we missed" lets the player record an untracked walk (today or yesterday only) with no GPS trail — it earns the identical treats/XP/stats/achievements reward as a tracked walk, no reduced treatment, but (unlike a tracked walk) never discovers or extends the Home Range on its own. Every `Walk` carries a `startSource` (`button` vs `manual-log`) to tell the two apart in storage. A manual log may optionally refresh the Bloom freshness of one route the player has previously walked with real GPS tracking — see Fresh Ground below — capped at 2 manual logs and 1 route refresh per calendar day.
- **The Home Range**: territory is a persistent 20m-square grid, not a polygon per walk. The **Range** is the permanent, monotonic outline of every cell any tracked walk has ever painted — it never shrinks. The **Bloom** is a colour-only freshness fill over that outline: each cell's "wildness" grows for up to 18 days since it was last walked, then holds steady — rendered as hue/saturation only, never as a number, with every cell equally visually present regardless of age. A `visits` count per cell drives a ghost-trail brightness channel so well-worn streets read as a brighter, denser vein. Rendering smooths the underlying grid with a Gaussian blur and a marching-squares contour so the Range reads as a soft rounded shape, not blocky cells. **Fresh Ground**: a qualifying walk's treats (never XP) are multiplied by `1 + 0.6 * meanWildness` of the ground it covered — up to ×1.60 for ground untouched in three-plus weeks, suppressed to no bonus at all below a ×1.25 display floor so a routine daily-loop walk shows no multiplier line. A manual log's route refresh always pays the same fixed ×1.112 regardless of which route is picked, so it can never out-earn an honestly-tracked walk. The Home Range also surfaces New Ground and "Buddy knows N streets" celebration beats. A colour gradient alone turned out to be unreadable at a glance (real on-device testing found no amount of opacity tuning fixes that), so a second, warm dashed **wild-ground contour** now circles ground wild enough to actually beat the Fresh Ground display floor, a single warm **marker** highlights the one most-worth-visiting wild cluster on the map, and a small map-screen **"Somewhere Wild" card** states the same fact in one sentence — a recent New Ground discovery for up to 48h, or an invitation back to that wild cluster, or (most of the time) nothing at all. Never the Den screen, never a push notification, never a number on the map itself. See `openspec/changes/home-range/design.md` for the full formulas and their validated worked values (`home-range-prototype.mjs`), `openspec/changes/home-range-rewards/` for the payout wiring, and `openspec/changes/somewhere-wild/` for the contour/marker/card legibility layer.
- **Storage**: walks, Den economy state, personal stats, and notification bookkeeping (overflow-already-surfaced flag, learned time-of-day bucket) each persist locally through a small repository layer, swappable for an in-memory fake in tests.
- **Economy**: a single config module holds every tunable number (upgrade costs, passive accrual rate, caps, Buddy's level-to-payout curve); pure formula functions built on top of it drive state transitions like awarding treats/XP and upgrading buildings. The reward-awarding path itself (`src/economy/walkRewards.ts`) is shared by both a tracked walk's closure and a manually-logged walk. The player's dog has a name (set once at first launch); the Den Level/XP number is framed as that dog's own level, and — as of `virtual-dog-companion` — the level itself now sets the per-walk treats payout rate (`buddyPayout`, boosted by the Sniff Garden's percentage bonus), so leveling up visibly pays out instead of being a bare progress signal. This is a deliberate, logged reopening of `den-level-xp`'s original "zero percentage impact" decision — see `openspec/changes/virtual-dog-companion/design.md`.
- **Notifications**: two local notification types, both scheduled via the same `expo-notifications` wiring with permission requested lazily (only at the moment a notification is actually about to be scheduled). The earned-trigger notification fires when the Den's treat storage overflows and hasn't already been surfaced, delivered near the player's own learned time-of-day walk pattern. The opt-in daily walk reminder (`openspec/changes/walk-reminder`, a named Phase 2 pull-forward exception — see `openspec/specs/game-phases/spec.md`) is off by default; once the player turns it on and picks their own time in Settings, it fires at most once a day, silently, only on a day no walk (tracked or manually-logged) has happened yet, and turns itself back off with no message after 3 consecutive days it fired but no walk followed. Rescheduled on every app open and immediately after any walk is saved — there's no backend to wake the app while it's closed, so a reminder can only ever re-arm after the app has actually been opened or a walk saved, not truly recur while fully killed.
- **The Doorstep**: the app's persistent home/overview screen — shown at every app cold start, right after the first-launch dog-naming gate and before the map, and shown again whenever the player dismisses the Den, Walk History, Stats & Badges, the burger menu's Debug Log or Log a Missed Walk, or the idle map's "back to Doorstep" control. Not a one-time splash: the only screen it can't be reached from mid-visit is the live map while a walk is actively being tracked (Finish Walk/Cancel only, until the walk ends). Layout: Buddy's name/Level/current milestone title, a still tappable portrait of the Home Range (Range outline + Bloom fill over OSM tiles, rendered in a hidden WebView and captured to an image; falls back to a neutral line if tiles don't load in time), a "while you were out" strip of 0-3 lines drawn only from already-computed facts (Somewhere Wild, an idle-accrued achievement, Den passive accrual, storage-at-cap, or the one-off territory-income reveal) — resolved once per app launch, not re-shown on later return trips this session — one Start Walk button, a small direct-access row (View Past Walks, Stats & Badges), a Den tease footer, a burger-menu control (Debug Log, Log a Walk We Missed), and (once revealed) a permanent territory-income line. The idle map screen lost its own six-button stack in favor of a single "back to Doorstep" control, now that Start Walk and the rest live on the Doorstep. Three session states (first-open-of-day, same-day re-open, long-absence) are derived from the existing `DenEconomyState.lastTickAt` — no new "last opened" field, no days-since-last-open number or copy anywhere (the hard anti-guilt rule). Shares the same `overflowSurfaced` bookkeeping the earned-trigger push notification uses, so the two channels never both fire for the same unclaimed overflow in one app-open. See `openspec/changes/home-dashboard/`.
- **Walk Portrait**: tapping a row in walk history opens a full-screen portrait of that one walk — its own recorded route (or, for a manual log, whichever previously-tracked route it refreshed, if any) drawn on once over ~1.2s on top of a muted, non-wildness-coded rendering of the aggregate Home Range, auto-fit to the walk's own bounds. Segments that were New Ground discoveries at the time finish drawing last, in a brighter green, via a live (never-captured) dedicated WebView — distinct from the Doorstep's static render-to-image portrait below, which this view only reuses for the one case it's actually correct: a manual log with no linked route, shown as the calm aggregate Home Range instead. A metadata row below shows date/place, distance, duration, and treats earned (date and treats only when there's no real trail to measure). No pace/speed colouring, rankings, comparison, or share action — a keepsake, not a stats screen. See `openspec/changes/walk-portrait/`.
- **Territories**: the single Home Range grid is partitioned into named, auto-discovered Territories — every cell belongs to exactly one, via `Cell.territoryId` (`src/storage/HomeRangeRepository.ts`), with Territory metadata (id, name, `createdAt`, `walksHere`, `treatsEarnedHere`) owned by a separate `TerritoryRepository`. A finished tracked walk's new ground either assimilates into an existing Territory within 400m or, if none is that close, births a new one (named via reverse-geocode, `src/utils/streetLookup.ts`'s `resolveTerritoryName`); two Territories merge only when their cells become literally 8-neighbour-adjacent, keeping the older Territory's name/id and summing its counters (`src/utils/territoryCluster.ts`'s `resolveTerritoryChanges`, called from `App.tsx`'s `finishWalk`). Each Territory's own card (`src/components/TerritoriesScreen.tsx` + `TerritoryCard.tsx`, opened via a button on the map screen) shows exactly four stats and, live-computed on every render, at most one character title ("Everyday"/"Wild One"/"Far One" — `src/utils/territoryTitles.ts`) — never a ranked comparison to another Territory. A second, additive passive-income term (`src/economy/territoryEconomy.ts`'s `territoryRate`, fed by `HomeRangeRepository.getWorldMass()`'s single ungrouped cell/visits aggregate — deliberately never grouped by Territory, so the total is provably unaffected by how many Territories a player happens to have) is hidden until it crosses 1 treat/hour, then shown permanently on the Doorstep and Den screens. See `openspec/changes/territories/`.
- **Buddy & game feel**: the app's look is pre-rendered 3D clay sprites made by headless Blender (`scripts/blender/`): Den buildings at 3 growth stages, icons, backdrops, and Buddy as layered parts per coat/ear/tail with a `manifest.json` of pivots. Buddy is an animated rig (`src/components/buddy/BuddyAvatar.tsx`) that defaults to the image skin (`src/buddy/imageSkin.ts`) and falls back to the vector skin per missing part; the player customises coat, ears, tail and size once (`BuddyAppearancePicker`, offered after naming the dog, editable in Settings). Mood (idle, happy, excited, sleepy, curious) comes from pure logic in `buddyMood.ts` and never reads as guilt: coming back after a break is a delighted greeting. Buddy lives on the Doorstep, the Den yard and the Celebration, never on the live walk map. The clay UI kit in `src/ui/` (Screen, Card, Button, Chip, ListRow, juice primitives, tokens) uses Nunito fonts loaded via expo-font. The Den yard scene is the hero of the Den screen, and the map is restyled with CARTO Voyager tiles under a pastel tint plus clay markers. `scripts/generateArt.mjs` is the optional Gemini/OpenAI path for a photo-likeness Buddy. See `openspec/changes/buddy-comes-alive/`.
- **UI**: the Doorstep, the map screen (with its Territories entry point), walk history and its tap-through Walk Portrait, the Den (building upgrades), a stats/achievements screen, the Territories list, and the "Log a walk we missed" entry point.

**State flow, in short:** start a walk → track GPS points, painting a live preview into the Home Range as it goes → Finish Walk saves the trail and paints its cells for real → if it covered enough ground (≥25 cells), award treats (at Buddy's current per-walk rate, times the Fresh Ground bloom multiplier) and Den XP (bloom-unaffected), and show a celebration screen (which also shows a level-up's old/new rate when one occurs, and a Fresh Ground/New Ground beat when either fired).

## Folder overview

- **components** — screens and UI pieces (the Doorstep home screen, its territory portrait, and its burger-menu overlay, map, walk history and its Walk Portrait, Den, stats, log-a-missed-walk, Settings (the opt-in walk reminder toggle/time picker), the "Somewhere Wild" card, the Territories list and its per-territory card)
- **economy** — balance config, formulas, and state transitions for treats/Den/stats (including milestone titles — the exact-milestone-only cliffhanger title and the Doorstep's persistent "current title at any level" readout — and the Territory passive-income formula, `territoryEconomy.ts`)
- **notifications** — decision logic and scheduling for both notification types: the earned-trigger notification (Den-economy overflow only, shared with the Doorstep's own overflow-line resolution) and the opt-in daily walk reminder (`walkReminderDecision.ts`'s pure ignore-streak/scheduling logic, `walkReminder.ts`'s orchestration)
- **storage** — persistence layer for walks, Den economy, personal stats, notification bookkeeping, the Home Range grid (including the New Ground event singleton row and per-cell Territory membership), and Territory metadata (`TerritoryRepository`)
- **utils** — GPS, geometry, the Home Range grid (cell addressing, freshness curve, painting, New Ground detection, splitting a trail into New-Ground/base colour runs for the Walk Portrait), manual-walk-log/calendar-day helpers (including the Walk Portrait's day-and-time-of-day phrase), wild-cluster selection (`wildSpot.ts`), reverse-geocode label resolution (`streetLookup.ts`), and the Territory clustering/merge algorithm plus character-title assignment (`territoryCluster.ts`, `territoryTitles.ts`)
- **web** — the map's, the Doorstep portrait's, and the Walk Portrait's web content, hosted in WebViews, including the Home Range raster builder and its Gaussian-blur/marching-squares/Lab-colour renderer (shared by the interactive map, the still Doorstep portrait, and the Walk Portrait's muted background layer)
- **openspec** — spec-driven build plan and game design docs (source of truth)
- **prototype** — clickable HTML design spec — match its visuals, not its structure
- **testing** — GPX routes for simulated walks
- **src/buddy** — Buddy's appearance model, palette, image skin (default) and vector skin (fallback); pure TS, no screens
- **src/components/buddy** — `BuddyAvatar` rig, `BuddyAppearancePicker` and the pure mood/trick logic
- **src/components/den** — the Den yard scene (hero of the Den screen) and its building sprites
- **src/ui** — clay UI kit (Screen, Card, Button, Chip, ListRow…), game-feel primitives and design `tokens`; see its README
- **src/art** — typed registry of pre-rendered sprites (`artOr` falls back to a drawn placeholder)
- **assets/art** — Blender-rendered PNG sprites (buildings, icons, backdrops); see its README for names
- **assets/buddy** — Buddy's layered PNG parts per coat plus `manifest.json` of pivots
- **assets/fonts** — Nunito (OFL) used by the UI kit
- **scripts/blender** — headless Blender sprite and Buddy renders; see its README
- **scripts** — `generateAssets.mjs` draws the app icon, adaptive icon, splash and favicon (`node scripts/generateAssets.mjs`; outputs are checked in); `generateArt.mjs` is the optional image-API art path
- **assets** — app icons, splash and images. After changing the icon or splash, rebuild the native app once: `npx expo prebuild --platform android && npx expo run:android` (JS changes still hot-reload)

See `CLAUDE.md` for collaboration rules and `openspec/` for the phased build plan and game design specs.
