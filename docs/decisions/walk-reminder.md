# Walk Reminder (shipped; 2026-08-22, reworked 2026-10-18)
**Why:** The founder forgot to start tracking one day and asked for a settings-based reminder. A clock-fired "did you walk yet" nudge is the riskiest pattern in the game (same shape as the guilt-mascot/streak/urgency patterns rejected in `docs/decisions/2026-08-22-walk-start-experience.md`), so it ships only as the fenced experiment resolved there: opt-in, player's own time, silent, auto-sleeping, skipped when already walked, one-tap-off, measured for 4 weeks against a kill condition.
**Decisions:**
- Off by default. New `src/components/SettingsScreen.tsx` (first Settings screen), reached from the burger menu (`DoorstepMenu`, since removed with the Doorstep); a dedicated screen because a native time picker inside a dismiss-on-outside-tap modal is a gesture/dismissal bug source.
- New native dependency `@react-native-community/datetimepicker` (via `npx expo install`, dev-client rebuild) for the time picker.
- Bookkeeping lives on the existing `NotificationRepository` row as flat `walkReminder*` columns (enabled, hour, minute, consecutiveIgnores, pendingDate, firedCount, followedCount, experimentStartedAt). First schema migration on an existing table: `ALTER TABLE ... ADD COLUMN` guarded against duplicate columns.
- Scheduling is one-shot DATE triggers via `expo-notifications`, re-planned on app open, after a tracked walk is saved, and after a manual log (and later when a tracked walk starts). Pure logic in `src/notifications/walkReminderDecision.ts`, orchestration in `src/notifications/walkReminder.ts`, tapping opens the home screen (was the Doorstep, since removed).
- Cancel by kind only (`data.kind === 'walk-reminder'`); never `cancelAllScheduledNotificationsAsync()`, it would kill the unrelated Den-overflow notification.
- "Already walked today" reuses `calendarDayKey` over `WalkRepository.getWalks()` (any `startSource`); that day is neither scheduled nor counted as ignored.
- Ignore = a scheduled day that passed with no walk (signal is walks, not app-open, since there is no foreground observer). Auto-off after 3 consecutive ignores flips the persisted toggle to off, with no message (honest Settings state).
- Off switch is the Settings toggle only, no confirm dialog. 4-week measurement via durable counters on the repository row, shown in a header block in `DebugLogScreen` once `experimentStartedAt` is set (not in the clearable debug log).
- Copy (approved): "There's a little more territory out there, whenever you two are ready for it." No title override. Never "you" as an order, no countdown, no guilt.
- **2026-10-18 rolling window (supersedes "exactly one reminder"):** on every app open and saved walk, cancel all and schedule the next `REMINDER_WINDOW_DAYS = 7` future days via `planReminderDates` (ids `walk-reminder-YYYY-MM-DD`, DST-safe local-field dates; today skipped if walked or time passed, window extends so 7 stay pending). Android channels `walk-reminder` and `den-overflow` (importance DEFAULT) created before any permission request; Settings requests permission on toggle-on, hint + `Linking.openSettings()` if denied. No `SCHEDULE_EXACT_ALARM` (inexact accepted). After 7 unopened days reminders stop.
- **2026-10-18 three slots:** Morning / Noon / Evening (`reminderSlots`: id, enabled, hour, minute, consecutiveIgnores; JSON column `walkReminderSlots`; defaults 08:00 / 13:00 / 18:30; legacy columns migrated by hour: before 11:00 Morning, 11:00-15:59 Noon, else Evening). Ids `walk-reminder-YYYY-MM-DD-<slotId>`, up to 21 pending. Planner skips a slot if a walk started in [previous enabled slot (00:00 for first), slot). Reconcile judges "followed" if a walk started in [slot, next enabled slot or 23:59:59]. Slots carry `enabledSince` (never judge days before it existed). Auto-off is per slot at 3. A manual log credits all windows of its day. One promise-chain mutex serialises replans. Foreground banner + sound now shown (replaces silent handler); Settings has diagnostics (permission, next trigger, planned count, "send a test reminder in 5 s"); schedules logged to Debug Log. Per-slot titles, body unchanged.
**Rejected:**
- `CALENDAR` repeating OS trigger, because it fires unconditionally (cannot skip when already walked without a live JS runtime) and keeps nagging forever, closer to the rejected daily-nag tone.
- Toggle/picker inside `DoorstepMenu`, because of nested-modal bugs; number-stepper instead of a native picker, because a worse control for a trivial dependency saving.
- Nested `walkReminder: {}` JSON column and a separate `WalkReminderRepository`, because the schema is flat columns and the repo already is notification bookkeeping.
- Notification action button ("Turn off"), because platform-divergent native surface; the settings toggle satisfies the guardrail.
- Deriving the 4-week numbers from the debug log text, because an unrelated "Clear Log" tap could destroy the decision data.
- One global walked-today rule, because a morning walk then silenced the evening reminder (the bug the owner hit); judging "followed" over the pre-reminder window, because every fired slot looked ignored and slots auto-offed for people who walk.
