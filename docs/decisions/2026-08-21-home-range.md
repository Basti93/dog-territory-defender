# Home Range: persistent grid replaces per-walk polygon (2026-08-21, implemented; rewards half in docs/decisions/2026-08-21-home-range-rewards.md)
**Why:** One shoelace polygon per walk (`locationsToPolygon`, `calculatePolygonArea`, `SHOW_ALL_TERRITORIES`) gave nothing for open walks, became a scribble after 100 walks, hid repetition, and claimed block interiors never entered. Concept by game-master; numbers validated by game-economist with a standalone prototype script (`home-range-prototype.mjs`, no longer in the repo).
**Concept:** Two layers. Range = monotonic outline of everywhere ever walked with GPS (never shrinks, even if a walk is deleted). Bloom = per-cell freshness shown as colour only. Rules: (a) never a number; (b) visible floor, wildest state after ~2-3 weeks then stops; (c) inversion: wilder patch pays MORE and looks inviting, never guilt (else it is the decay mechanic virtual-dog-companion ruled out). Headline stat in words ("Buddy knows N streets"), never a percentage. Range size never on a leaderboard. Phase 3 neighbour effects only reserved, not built.
**Decisions:**
- Grid: `CELL_M = 20`, `dLat = 20/111320`, `dLon(iy) = 20/(111320 cos((iy+.5)dLat))` from the ROW (pure, no drift); cell = `(ix, iy)`. 20 m because drift <10 m moves a fix at most one cell; 10 m quadruples storage, 50 m exceeds a street.
- Paint: cells whose centre is within `PAINT_RADIUS_M = 25` of the path resampled every 5 m. Guards: `MAX_SEGMENT_M = 60`, `MAX_SEGMENT_SPEED_MS = 4.5` (no painting through dropouts, trams, bikes). 1.5 km loop = 165 cells; ribbon ~2.48 cells (~50 m); full repaint 0.5 ms; no DB write per fix (batch at walk close); freshness computed lazily, never stored decaying.
- Cell record: `ix, iy, lastRefreshed` (bloom clock; tracked walk, manual refresh, future neighbour), `lastTracked` (GPS only; keeps manual logs out of any future defence logic), `visits` (tracked only, monotonic, ghost-trail brightness; must ship WITH bloom, see flag 1). Phase 3 hook: `lastRefreshed += a*(now - lastRefreshed)`.
- Wildness: `w(d) = (1-e^(-d/5)) / (1-e^(-18/5))` for 0<d<18, 1 for d>=18 (`TAU_DAYS = 5`, `D_MAX_DAYS = 18`, divisor 0.97268 so it hits exactly 1). Day 1 = 0.186, day 7 = 0.775, day 14 = 0.966. Ramp `#2ECC71` to `#DCE8BE` in Lab/Oklab (not sRGB: loses ~26% of the one-day step); one-day step dE 10 (>4 JND). Render continuously or >=24 bands.
- Rule (b) floor is carried by alpha, not wildness: `fillAlpha = 0.6` flat for every Range cell (raised from 0.28, too faint on real tiles; rendering fix, rule unchanged). `visits` nudges toward saturated green via colour-mix.
- New Ground: `painted cells not in Range AND no 8-neighbour in Range` >= `NEW_GROUND_MIN_CELLS = 12` (Range snapshotted at walk start). Dilation is essential: without it 200/200 false positives at sigma 8 m. With it 0/200 up to sigma 20 m (max 9). Fires at ~220 m out-and-back on an unwalked street (13 cells).
- Headline: `streetsKnown = max(1, floor(rangeCellCount / 11))` (`CELLS_PER_STREET = 11`, ~90 m block). One 1.5 km walk = 15; a year = 36-264.
- Rendering: render-only Gaussian blur sigma = 1 cell on occupancy raster, 0.5 iso-contour (marching squares): 1-2 stray cells and 2x2 blocks vanish, ribbons >=2 cells wide survive. New Ground uses RAW cells, never the contour (model and render share no threshold). Bridge: one bounded raster message `{origin:[ix0,iy0], w, h, wild: b64 Uint8, visits: b64 Uint8}` (125x125 window ~21 KB), replaces unbounded polygon list.
- Storage: ~60 B/row; 495 cells/yr (3-loop walker) to 31 416 cells ~1.8 MB (pathological); Range is the one unbounded number (viewport query needed eventually).
- Fresh Ground payout (built in home-range-rewards): `bloomMultiplier = 1 + 0.6*B`, B = mean wildness of painted cells (new ground = 1.0), 1.0 if <25 cells; max x1.60; treats only; shown only if >= 1.25. Spends 0 pp of the 30 pp budget (no level/building/balance term; ratio L100 vs L1 identical with/without bloom). Walking less never pays more (income/30 d falls strictly with interval).
- Technical split: this change = grid, storage, one-time migration, painting, New Ground, WebView rewrite, XP area term. No bloom treats yet.
- Loop-closure retired: painting decoupled from closure; `canCloseWalk`, `MIN_CLOSURE_RADIUS_M`, `CLOSURE_ACCURACY_MARGIN_M` deleted; buttons collapse to Finish Walk / Cancel. Reward gate moves from ">=10 GPS points AND start-end within ~100 m" to `MIN_CELLS_FOR_REWARD = 25` painted cells (~200 m, any shape). Below it the walk still saves and paints but earns no treats/XP. Single floor replaces the unimplemented >=200 m/>=5 min one.
- XP area term: `xpAwardForWalk = 20*baseMult + 15*km + 5*min(cellsPainted*400, 20000)/1000` (400 m2 per cell; cap now binds at 50 cells; unvalidated against real data).
- Migration: every stored walk with a real `locations` trail replayed once, seeded with its own `startTime` (old ground reads wild); manual logs contribute nothing; idempotent singleton-row flag; no retroactive treats/XP.
- Flag 1 (resolved by game-master): twice-a-day fixed-loop walker stays at wildness 0.088-0.107 forever (dE 1.0, invisible); not fixable by tau/K. So `visits` brightness (loyalty axis, slow, never tops out within a year) ships with bloom, plus the x1.25 display threshold. Flag 2: bloom averages +15% vs Sniff Garden max +8%; keep K = 0.6 (K=0.3 gives 1.23x best:routine, "a bigger number"); Den-as-footnote is a presentation issue, never show Den % and Fresh Ground on one screen.
**Rejected:**
- Buffered polyline blob, because it has no addressable units for per-patch clocks and Phase 3 needs them.
- `W_new = 1.4` for new ground (x1.84 ceiling), because it adds a second bound and favours holiday walkers over rediscovering the home area.
- Bloom on XP, because XP feeds Level feeds income (compounding) and den-economy fences XP inputs.
- Keeping loop closure as a dead gate, because it existed only for the shoelace formula.
