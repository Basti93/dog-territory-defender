- 2026-10-25 · Bug fix (prod, Android 0.3.0: walk "ran" 4 h, logs stopped 08:37:40, white screen after swiping the app away, then "database is locked" on every write): storage hardened, JS-only (OTA). Cause: the process outlived the app (foreground service), a second JS runtime opened its own connection with no busy timeout and the rollback journal, while the first connection held the write lock; nothing in JS had a timeout, so a store call that never answered held up the launch (no `ready`/`loaded`, blank view) and the 60 s tick (`syncStoredFixes` awaited the load before the auto-finish decision). Now: one shared connection per file (`storage/database.ts`: `busy_timeout` 5 s, WAL, 15 s open timeout), `dbLock` has wait (60 s) and hold (30 s) limits with `DB_LOCK_TIMEOUT` logged and always ends the transaction (`BEGIN IMMEDIATE`, rollback on error or hold timeout), bounded reads at launch (locale 5 s, first-screen reads 20 s, restore load 15 s, store sync 10 s), a calm retry screen (`StartupTroubleView`, stops the location service so Android can drop the lock) instead of a blank view, and a headless watchdog (`staleWalkWatchdog.ts`) that stops the location task of a walk silent for 3 h + 5 min (the stored walk is finished by the next restore). No threshold in walk-lifecycle.md changed; the spec gained the storage rule.
