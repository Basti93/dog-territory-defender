- 2026-10-18 · Game design (game-master approved): walked distance ignores implausible steps. Old: `cumulativeDistance` summed every step, so GPS jumps, tram/car rides and the gap after an iOS force-quit inflated distance, XP and km (`paintedCells` already skipped steps over 60 m or 4.5 m/s). New (`stepCountsAsDistance`, constants beside the paint filter in `src/utils/grid.ts`): a step counts if (normal) <= 60 m AND <= 4.5 m/s, or (dropout bridge) 60-250 m AND <= 180 s AND average <= 2.0 m/s; missing or zero time delta counts only up to 60 m. Silent: no "x m not counted" text. Not retroactive: `cumulativeDistance` is the filtered sum, `cumulativeDistanceLegacy` the old; `walkDistanceMeters(walk)` picks by `startTime` against `DISTANCE_RULE_SINCE_MS` (2026-10-18 19:35 UTC) wherever distance is recomputed from points (Walk Portrait, prior-walk XP average in `walkRewards.ts`, partner-walk note in `sync/apply.ts`, server `services/walks.ts` XP, `neighbours/coop.ts` weekly km); stored lifetime stats/records never recomputed. App and server share it via `@game/utils/geometry`; live map and `finishTrackedWalk` use the same function. Trail lines cut at failing steps (`splitAtGaps`, web copy `src/web/gapSplitScript.ts` with an agreement test). Known edge: the server simplifies a partner's presence thread to 400 points, so a simplified step above 250 m or 180 s can show a gap (presentation only).
