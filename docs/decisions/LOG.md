# Decisions log

Dated bullets, newest first. Game-design changes name the spec file and the old/new value; presentation decisions name the screen or asset. Older, per-change proposals and designs live in the sibling folders.

- 2026-10-18 · Game design (game-master approved): walked distance now ignores implausible steps. Old behaviour: `cumulativeDistance` summed every step between fixes, so GPS jumps, tram or car rides during a running walk and the gap after an iOS force-quit inflated distance, XP and kilometres (`paintedCells` already skipped steps over 60 m or 4.5 m/s, distance did not). New rule (`stepCountsAsDistance`, constants beside the paint filter in `src/utils/grid.ts`): a step counts if (normal) at most 60 m AND at most 4.5 m/s, or (dropout bridge) 60-250 m AND at most 180 s AND average at most 2.0 m/s; missing or zero time difference counts only up to 60 m. Why: stop rewarding rides and jumps without punishing an honest tunnel or sleeping phone. Silent: no "x m not counted" anywhere. Not retroactive: `cumulativeDistance` is now the filtered sum, `cumulativeDistanceLegacy` the old one, and `walkDistanceMeters(walk)` picks by `startTime` against `DISTANCE_RULE_SINCE_MS` (2026-10-18 19:35 UTC), so walks started earlier keep their old distance wherever it is recomputed from points (Walk Portrait, prior-walk XP average in `walkRewards.ts`, partner-walk note in `sync/apply.ts`, server `services/walks.ts` XP and `neighbours/coop.ts` weekly km); lifetime stats and records are stored incrementally and never recomputed. App and server share the code via `@game/utils/geometry`. Live map distance (`MapScreen`) and finish distance (`finishTrackedWalk`) use the same function. Trail lines are cut at failing steps (`splitAtGaps`, web copy in `src/web/gapSplitScript.ts` with an agreement test), used by the live Trampelpfad, Alex's thread and the Walk Portrait. Known edge: the server simplifies a partner's presence thread to 400 points, so on a very long straight stretch a simplified step above 250 m or 180 s can show a gap in the thread (presentation only).
- 2026-10-18 · Performance: `useViertelChrome` no longer loads every walk with all fixes on each mount; `WalkRepository` gained `countClosedWalks()` and `getLastWalkEnd()` (SQL count; newest walks parsed first, usually one row), and the Somewhere-Wild pin it resolves for the scene goes through `evaluateSomewhereWildShared` (once per data version = refreshKey, dog name and repository, reused for 20 min, failures not remembered) instead of a full evaluation on every mount.
- 2026-10-18 · Bug fix/Architecture: a walk in flight survives closing the app. Cause: the active walk lived only in memory (`useWalkSession`'s `walkRef`), so after a swipe-away or kill, a tap on the "Tails Up" notification or the icon opened a fresh Doorstep and the walk was gone. Now `ActiveWalkRepository` (SQLite tables `active_walk` + `active_walk_fixes`, created IF NOT EXISTS; in-memory fake for tests) is the durable mirror; `walkRef` stays the source of truth while running. `activeWalkRecorder.ts` writes it in batches (every 10 fixes or 15 s, and on AppState background) from `gps.ts`'s `deliver()` via `setFixRecorder`, so fixes reaching a UI-less or headless-relaunched runtime are saved too; started in `startWalk`, cleared after the finished walk is saved and on cancel. At launch (`useWalkRestore`, once the first-launch state is loaded): newest fix under 3 h old and auto-finish (replayed over the stored fixes, `restoreWalk.ts`) not done -> `resumeWalk` (same points/start/mode, location task restarted, live map opens, `WALK_RESTORED`); older than 3 h, or auto-finish says done -> normal `finishTrackedWalk` path (`WALK_RESTORE_FINISHED`, endedBy `auto-still`/`auto-home`, celebration as usual); fewer than 2 fixes and older than 3 h -> discarded quietly. A walk id that is already saved is dropped, a busy session is never touched (no duplicate walk). With no stored walk, a location task that outlived its walk is stopped. The Android foreground-service notification is expo-location's own (plain launcher intent, no payload), so a tap is not distinguishable from an icon tap: routing to the map happens on restore only; a warm resume never navigates. iOS: after a force quit updates stop until the app opens again; the walk resumes with a gap. `paintedCells` already refuses any step over 60 m or 4.5 m/s, so a jump paints nothing; distance (`cumulativeDistance`) is deliberately unchanged, so a long jump still counts as distance (open point, see report). No game numbers changed; the 3 h and 15 s/10 fix values are plain constants in `restoreWalk.ts` / `activeWalkRecorder.ts`.
- 2026-10-18 · Presentation: Viertel fit and display names (follow-up to the embedded Viertel). Fit: the band frames the cluster of our newest paint (`src/web/embeddedFit.ts`: cells within 12 cells form a cluster; nearest other clusters are added only while the union stays within 60 x 46 cells = what fits at zoom 15; one huge cluster is cropped to a window around the newest cell), widened for nearby neighbours and the partner thread; the wild pin never takes part in the fit and may sit off-screen. Embedded zoom is clamped to 15..17 (a tiny Range never zooms out to the city, a scattered one is cropped, not shrunk). Notes whose point lies outside the fitted view are hidden in the page (`filterMapNotes` on every `moveend`), so "heute genäht" only shows when its cell is in view. Territory names: generated defaults are stored in the language of the moment (client "{dog}'s New Range" / "{dog}'s {place} Range", server "A new corner"), so `displayTerritoryName` (`src/utils/territoryDisplayName.ts`) re-renders them in the current language at display time (Viertel sign, Territories card, Somewhere-Wild card place, homecoming place lines); a name the player typed is never touched. New key `territory.name.serverDefault` ("Eine neue Ecke"). Scene polish: the fence sign shows dog name on line 1 and title on line 2 (shrinks to fit, never breaks mid-word), and the "↑ zum Viertel" hint gets a trailing no-break space plus side padding because Android clipped the handwriting font's last glyph.
- 2026-10-18 · Presentation: Viertel = live embedded patchwork map (presentation only, no economy numbers). The scene's Viertel band no longer shows a captured `TerritoryPortrait` image; it is one non-interactive `MapView embedded` WebView (`mapHTMLEmbedded`, init flag `const EMBEDDED`: no drag/zoom/tap/zoom control, `zoomSnap 0.25`, still clouds so it never repaints on its own) filling the band's full width and height, fitted to our Range (plus the nearest neighbours and a partner's live thread, bounding box only) with `maxZoom 17` and padding for the signs. A Pressable over the map opens the full map; the full-screen `MapView` is a second instance only while it is open. Because the Viertel layer's parallax pushes it up by `0.15 * startOffset` at scroll 0, the map is that much taller than the band (`bottomInset`): tiles fill it, the Range fit, the empty-Range centre and the numbers sign stay clear of it. Chrome (scene band and idle `MapScreen`): rotated `WoodSign` with the territory of the latest walk and its character title (top left), paper "Reviere ›" sign (top right, opens Territories; replaces the old emoji button), paper numbers sign bottom left ("{walks} Runden · {streets} Straßen · {corners} Ecken"; household's own: closed walks from the walk repo, streets = `streetsKnown(range cells)`, corners = 0 until a named-corner data model exists, a zero part is hidden, no comparisons). Handwritten notes come through the new `SHOW_NOTES {notes:[{text, lat, lon, anchor?, kind?}]}` message (Leaflet divIcons, Caveat embedded as a 29 KB Latin subset in `src/web/caveatFont.ts`, regenerate command in the file): "heute genäht" below the cell painted most recently today, "hohes Gras, noch nie dort" above the Somewhere-Wild pin, and a chalk "Platz zum Entdecken" at the centre while the Range is empty (`SET_VIEW` zoom 16 on the last walk's end or the last known device position, never prompting; with neither, linen plus the chalk text and no WebView map). Data comes from `useViertelChrome` (loads once per mount/refreshKey, no timers; the scene resolves the wild pin with `evaluateSomewhereWild`, the map screen reuses the card's spot). `TerritoryPortrait` keeps only the plain Range still (Doorstep/territory cards); its neighbour/partner-thread props and test were removed (the portraitHTML-side drawing code for them is now unused). The "Trampelpfad" is not drawn in the scene (no trail data outside a live walk).
