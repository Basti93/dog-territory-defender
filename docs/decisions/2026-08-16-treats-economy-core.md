# Treats economy core (2026-08-16, implemented; numbers since evolved)
**Why:** Phase 1's hypothesis ("claiming territory plus passive treats makes you want to walk tomorrow") needs a real economy. den-economy and anti-snowball specs described it qualitatively, nothing was implemented. Built as a config-driven, unit-tested core without the Den UI. Specs unchanged (exact numbers are config defaults documented here).
**Decisions:**
- One config `src/economy/balanceConfig.ts` (`BALANCE`) holds every tunable. Pure formulas in `formulas.ts`: `upgradeCost`, `storageCap`, `passiveTreatsPerHour`, `softCapBonusPercent`. State transitions in `denEconomy.ts`: `applyPassiveAccrual`, `awardWalkTreats`, `upgradeBuilding` (returns `{error: 'insufficient-treats' | 'max-level'}`, not exceptions).
- Original numbers (from the prototype): treatsPerWalk 50, startingTreats 50, storage `100 + doghouseLevel*100`, costs `costBase*costMult^level` with doghouse 40/1.5, bakery 60/1.6, sniffGarden 50/1.45, `maxBuildingLevel = 100`. Still in `BALANCE`: startingTreats, building costs, passive 1 treat/hour per Bakery level, softCap `{level:50, maxBonusPercent:50, curveRate:25}`. Flat `treatsPerWalk` is gone from `BALANCE`; `buddyTreatsPerWalk` replaced it, and `storageCap(doghouse, buddy, bakery, sniffGarden)` (income-based, with a never-softlock floor) and `passiveTreatsPerHour(bakeryLevel, buddyLevel)` now also take Buddy level (bit-identical at Buddy level 1). The 1 treat/hr default is an invented, unvalidated number (retune in one line).
- Soft cap `bonusPercent(level) = maxBonusPercent*(1 - e^(-level/curveRate))`: ~43% (86% of cap) at level 50, creeping toward 50. Applies only to %-bonus buildings (Sniff Garden); Doghouse storage and Bakery passive are personal throughput and skip the cap (revisit when Phase 3/4 buildings land). Later: Sniff Garden got its own `sniffGarden: {maxBonusPercent: 8, curveRate: 25}` and `softCapBonusPercent` became display-only dead code (see docs/decisions/2026-08-21-virtual-dog-companion.md).
- Persistence: single row, key `'singleton'`, table `den_economy(id, treats, doghouseLevel, bakeryLevel, sniffGardenLevel, lastTickAt)`; repository mirrors `WalkRepository` (`getState()` creates the default row, `saveState`; SQLite + in-memory + contract tests).
- Passive accrual computed on read (elapsed since `lastTickAt`, capped at storage cap, advance `lastTickAt`), no background timer; correct whether the app was closed 5 minutes or 5 hours.
- Known risk: on-read accrual is gameable by changing the device clock; fine for a single local player, a server-authority concern once sync exists.
**Rejected:** (non-goals) Den UI, collectibles effect for Sniff Garden (Phase 2), checking the ~30% total advantage at L100 until more %-buildings exist.
