# Walk Portrait (shipped; screen removed 2026-10-18, data and renderer reused by postcards)
**Superseded:** the Walk Portrait screen and `WalkHistoryScreen` were removed on 2026-10-18; postcards on the bench and the Album replaced them (see LOG.md 2026-10-18). The persisted fields, `splitTrailByNewGround`, `renderHomeRangeMuted` and `src/web/walkPortraitHTML.ts` live on and feed the postcard map (`src/components/postcards/PostcardMap.tsx`).
**Why:** The history list was a bare list (date, "Rewarded"/"Too short", point count), rows not tappable. Goal: make a past walk worth looking back at (exact route redrawn once inside everywhere the dog has been) without turning history into a stats/comparison tool, and without manual logs feeling second-class.
**Decisions:**
- Animation is feasible but NOT via the `TerritoryPortrait`/`portraitHTML.ts` capture path: that pipeline yields one `toDataURL()` image, and animating would need 30-70 tile-fetching captures. Instead a new live, never-captured, non-interactive Leaflet WebView (`src/web/walkPortraitHTML.ts`, modeled on `mapHTML.ts`; dragging/zoom/keyboard all off), fed one `RENDER_WALK { walkLatLngs, newGroundCellIds, raster }` message; trail drawn on in-WebView by growing the `setLatLngs` array over ~1.2 s.
- Two-phase reveal so New Ground "finishes last": phase A (~70% of 1.2 s) draws the whole trail chronologically in base colour, phase B (~30%) recolours the New Ground runs. The 70/30 split is an unvalidated first-pass number.
- Two render states: walk-trail (tracked walk, or manual log with linked route) = live WebView; manual log with no linked route = `TerritoryPortrait` reused unmodified (static aggregate Range, "here's everywhere Buddy knows"; empty Range shows the "hasn't marked the map yet" copy).
- Muted background: new `renderHomeRangeMuted(map, payload, previousLayerGroup)` sibling to `renderHomeRangeToMap`/`renderHomeRangePortrait` (same blur + marching-squares, flat single tone, no wild contour, no marker, reduced opacity). Trail colours reuse tokens: base `HR_WILD_HEX` `#DCE8BE`, New Ground `HR_FRESH_HEX` `#2ECC71`. One new token formalised: muted grey `#8A9A8A` (context/background chrome), already used informally as UI text colour.
- New Ground per walk is not recoverable from stored data (`NewGroundEvent` is a singleton with no walk id; `Cell` has no first-painted time), so add `Walk.newGroundCellIds?: string[]` = the already-computed `newGroundCells(...)` set, written at finish. Pure `splitTrailByNewGround(locations, newGroundCellIds)` in `src/utils/grid.ts` returns contiguous `base`/`new-ground` runs (one `L.polyline` per run). Walks saved before have no highlight (uniform trail, by construction); permanent gap, no backfill.
- `Walk.treatsEarned?: number`: not persisted before; written by a second idempotent `saveWalk` upsert after `awardWalkRewards` resolves (the walk must already be saved first because `walkOrderForDay` counts saved walks). Distance = `cumulativeDistance(locations)`, duration = last minus first `timestamp`; both derived, never stored.
- `Walk.refreshedRouteWalkId?: string`: manual-log route refresh was not remembered; set where `refreshApplied` becomes true. Deleted route (`getWalk` returns null) must fall back to the no-trail state, never an error.
- Metadata row: date/place + distance + duration + treats; manual log with no linked route shows date + treats only (no locations, no distance/duration).
- Place title: `resolveLabelForPoint` from `src/utils/streetLookup.ts` on the walk's start point (`locations[0]`, or linked route's), cache key `walk-portrait:${walk.id}`. New pure `dayAndTimeOfDayPhrase(timestamp)` ("Tuesday morning") in `src/utils/manualWalkLog.ts` (hour buckets are an implementer call).
- State lived in `App.tsx` as `viewingWalk: StoredWalk | null` (nullable-object pattern like `celebration`), later replaced by the postcards flow.
- Copy decisions (accepted as recommended, 2026-08-22): New Ground is colour-only, no text; "Short stroll" replaces "Too short"; no end-of-trail marker (paw marker at start only).
**Rejected:**
- Reusing the capture pipeline for animation, because it is a one-shot export.
- Anti-scope (never build): pace/speed colouring, best-walk/records/ranking/sorting by distance, two-walk comparison, share/export/screenshot button, coverage-gap highlighting. Deferred: pinch-zoom/pan, time scrubbing, historical wildness reconstruction, list-row thumbnails.
- Query-time recomputation of New Ground, because the data does not exist after the fact.
