# Home dashboard "The Doorstep" (2026-08, shipped; superseded)
**Superseded:** the Doorstep, Den and Celebration screens were removed on 2026-10-18 in favour of the "Unser Viertel" world scene (`src/components/world/WorldScene.tsx`). Surviving pieces: `src/components/doorstepSession.ts` (session/away-strip rules), `src/components/TerritoryPortrait.tsx`, `src/web/portraitHTML.ts`, `currentTitleForLevel` in `src/economy/milestones.ts`.
**Why:** the app opened straight onto the map with no "what has your dog been up to" moment. Goal: a warm, low-pressure landing screen (Buddy, territory, what changed while away) with no new guilt/streak mechanic and no new economy logic. Anti-guilt is structural: a player away three weeks gets the same flow as one opening the app twice a day.
**Decisions:**
- Presentation layer only: every number traces to an existing tested function. Layout: dog row (name, Level, current title, "brings home N treats a walk"), territory portrait (Range outline + Bloom fill, no pins), "while you were out" strip (0-3 lines), one Start Walk button, icon row (Past Walks, Stats & Badges), Den-tease footer (`getUpgradeTease`, `storageCap`), burger menu (Debug Log, Log a Walk We Missed).
- `currentTitleForLevel(level)`: title of the latest milestone at or below `level`. `titleForLevel` returns non-null only on exact milestone levels (cliffhanger use). Level 1 returns null (title segment omitted); past the 8th title it keeps "Horizon Chaser".
- Portrait: user chose OSM tiles behind the shape (2026-08-22). Separate minimal non-interactive WebView (`portraitHTML.ts`, cut-down `mapHTML.ts`), `RENDER_PORTRAIT` in, `PORTRAIT_READY {dataUrl}` / `PORTRAIT_FAILED` (tile timeout) out; falls back to dog + neutral line, never a broken image. Not rendered when there are no cells. Separate from `MapView`'s WebView so a slow portrait cannot affect the map. Render time at thousands of cells unmeasured. (Later: CARTO Voyager tiles, CORS for capture unverified, same fallback.)
- Session state reuses `DenEconomyState.lastTickAt` (value before the mount effect overwrites it); no new field. `resolveDoorstepSession(previousLastTickAt, now)` gives `same-day-reopen` or `fresh-open` with `greetingFlavor` `first-open` (gap 0-1 calendar days) / `long-absence` (2+ days, reuses the today/yesterday boundary of the manual-log window and New Ground's 48h window; unvalidated first pass). Both flavours render the identical flow.
- Hard guardrail: the day-gap number may only pick a greeting copy pool; it must never appear in any user-facing string (no days-since counter, no apology copy).
- Away-strip priority on `fresh-open` (cap 3): (1) `evaluateSomewhereWild()` text verbatim, (2) first pending idle-accrued achievement ("Earned: {name}."), (3) treats: storage-at-cap line wins over "Treat Bakery baked {accruedDelta} treats.", (4) anchor line "Buddy's Bakery bakes faster the more he walks." only if 1-3 are empty, flat 25% chance, `Math.random()`. `same-day-reopen`: cap 1, same order, phrasing "+{accruedDelta} in the bowl.", no anchor.
- Overflow line vs push notification: sequence in one async routine in `App.tsx` (Doorstep overflow check and its `overflowSurfaced` write first, then `checkAndScheduleEarnedTriggerNotification`), otherwise a push could fire for an overflow the player is already looking at.
- `accruedDelta` and `pendingDenAchievements` are passed down as already-computed props (re-deriving after `lastTickAt` advanced gives ~0). Achievement surfaced here calls `onAcknowledgePendingAchievements` (broadened `personal-stats` Achievement Unlock Presentation beyond the Den). Shared day-diff helper extracted into `src/utils/manualWalkLog.ts`.
- 2026-08-22 reversal (founder, on device: could not get back to the new home screen): Doorstep is the persistent home, not a once-per-launch gate. Every screen's `onClose` also does `setShowDoorstep(true)` (Walk Portrait and Territories keep nesting); "New Walk" returns to it; the idle map loses its six-button stack for a single back control owned by `App.tsx`; notification-tap now also `setShowDoorstep(false)` (Den previously never opened on cold start).
- Remount fix: `resolveDoorstepSession`, `resolveAwayStripLines`, `pickGreeting` are resolved once per launch in `App.tsx` and passed as props, else every return trip replayed "+N in the bowl". Den state and portrait cells are still re-fetched per mount.
- Icon row has History and Stats only (Den already reachable via the footer tease). Log a Missed Walk goes in the burger menu (occasional recovery action, 2/day cap); menu is a local RN `Modal` state inside the screen, not an `App.tsx` boolean.
- Collect-tap sound resolved as visual-only (RN `Animated` fly into the footer counter); no audio dependency then.
**Rejected:**
- Navigation library or a single `screen` enum, because the fix was a few `onClose` lines.
- Keeping the Doorstep permanently mounted under overlays, or a module-level "resolved" flag, because of bigger architecture change / hidden mutable state.
- No-basemap portrait (original recommendation), overridden by the user.
