# Buddy comes alive: animated dog, juice, art direction, presentation log (2026-10-17..18, shipped)
**Why:** the app worked end to end but looked like a prototype (emoji dog, grey circles, no press feedback, no transitions, no icon/splash). Owner wants to use it daily and have it "look and feel like a complete game" with an animated dog "like Nintendogs" that resembles his own. `visual-design` already required tail wag, ticking counter, gentle confetti. Presentation only: no mechanics, numbers or reward-affecting state.
**Decisions:**
- Buddy = procedural, customisable avatar (coat, markings, ears, tail, size, accent), chosen after dog-naming (skippable), editable in Settings. Model/palette in `src/buddy/buddyAppearance.ts`; persisted in singleton table `buddy_appearance` via `BuddyAppearanceRepository` (`getAppearance`/`saveAppearance`/`hasChosen`, `normalizeAppearance` falls back to defaults). First-launch step is a local `needsAppearance` flag (no persisted flag). Coat palette (8 coats, 3 accents, 3 nose/tongue) is an ADDED visual-design requirement, avatar-only, never UI chrome.
- Animation: built-in `Animated` (native driver) + `react-native-svg`; each piece is an `Animated.View` holding a static `Svg`; max 12 animated nodes (target 10); `transformOrigin` for joints. Moods `idle`/`happy`/`excited`/`sleepy`/`curious`; priority transient > sleepy > curious > idle. Pure logic in `src/components/buddy/buddyMood.ts` (`resolveBuddyMood`, `pickTrick`, `nextTrickDelayMs`, injectable rng).
- Anti-guilt departure: long absence gives an `excited` greeting, never sleepy. Sleepy only for `same-day-reopen` and 22:00-06:00. Mood and greeting are resolved once per launch in `App.tsx` and passed as props (re-resolving per mount replayed the burst).
- Shared juice in `src/ui/`: `PressableScale`, `AnimatedNumber` (JS-driven, <=800 ms, <=2 on screen), `Confetti` (24 pieces), `TreatPop`, `FadeSlideIn` (never wrapped around a WebView screen: blank on Android), shared `tokens.ts`. Start Walk pulse: 2-3 cycles scale 1.0 to 1.03 on `fresh-open` only. No Buddy on the live map (phone-in-pocket).
- Art style (founder): pre-rendered 3D clay sprites, animated in code; registry `src/art/artAssets.ts` with vector/flat fallback. Headless Blender (`scripts/blender/`) preferred for buildings/icons/backdrops (deterministic, one shared rig); `scripts/generateArt.mjs` (Gemini/OpenAI) for Buddy likeness from a photo. Icons/splash from `scripts/generateAssets.mjs` (raw RGBA + `node:zlib` PNG, zero deps); needs native rebuild to show. Blender sizes: icons 256, buildings 512, burst 768, sky 1024, yard 1536x1024. Buddy = per-coat layered 512px parts via image skin (`src/buddy/imageSkin.ts`, `imageSkinSources.ts`, pivots hard-coded from `manifest.json`); `vectorSkin` is per-part fallback; size = uniform scale about the feet (small 0.88, large 1.12). Later added markings overlay, lying pose, walk frames.
- Den art: 5 stages by building level (`ART_TIER_2/3/4/5_FROM_LEVEL` = 4 / 10 / 20 / 35, `src/components/den/YardScene.tsx`), stage size ~50/72/92% of frame; presentation thresholds, tune freely. Clay UI kit + Nunito app-wide (flat UI clashed with sprites). Map: CARTO Voyager tiles + pastel tint (attribution required). Yard hero ~48% of screen height, clamped 340-440.
- i18n: dependency-free `src/i18n` (`t`/`tPlural`, en/de, key-parity tests), locale pref `system|de|en` in `SettingsRepository`; German glossary at top of `de.ts`.
- Yard life: wander clock in `src/components/den/yardLife.ts` (15-30 s waits, ~90 px/s, 3-6 hops, native-driver only, x-only on the front ground line, 52 px edge clamp). Wild Extras (`wildExtras.ts`): max one per Den open, once per local day each, 40% `AMBIENT_CHANCE` on open-triggered ones, triggers e.g. 3 km walk (`LONG_WALK_KM`), every 10th walk, weekend, Oct/Nov, 14-18h; no unlock/counter/streak on extras. Rare idle tricks at 1/6 of trick weight.
- Onboarding: cards -> name -> look -> permission primer -> home, via `resolveFirstLaunchStep` (`src/components/onboarding/firstLaunch.ts`); `onboardingDone` in `SettingsRepository`, written after the primer; launch-time location request skipped on fresh install; asks optional, declines answered calmly.
- Audio (`src/feedback/`): one kalimba/marimba voice, C major pentatonic, peak -6 dBFS; walk cues in `walkCues.ts` (new-street ding needs >=3 new cells and >=20 s gap; reward-reached once at `MIN_CELLS_FOR_REWARD`; walk-done skipped if celebration jingle plays); ambient music box only on home/Den/celebration, never in a walk, fades after 5 min. Owner decision: no sound while app is not active (`shouldPlayNow`), `UIBackgroundModes` audio removed.
- Gentle OTA updates (`expo-updates`): background download, flag only, meadow card "restart now?", never during a walk. Auto-finish forgotten walk (`src/app/autoFinish.ts`): >= 8 min, within 40 m of start after >= 150 m away for 3 min, or 20 min still (< 25 m); same rewards; per-player switch default on.
- Redesign steps 1-4 (2026-10-18): one scene with three heights (`WorldScene.tsx`, replaces Doorstep + Den yard; upgrade logic moved to `src/app/useDen.ts`); "Heimkehr" replaces the celebration screen (`Homecoming.tsx`, `homecomingPlan.ts`, one tap per beat); `WoodSign` 9-slice sprites, Settings as "Post" paper sheet; bakery loop visible (`BakeryLife.tsx`, `bakeryRules.ts`: emit interval = 3600000/rate clamped 3-12 s, max 6 in the air, none at cap or during a walk; bowl count is display-only projection, real accrual unchanged).
**Rejected:**
- Photo import / photo-to-avatar ML, free-form colour picker, because uncanny, native dependency and off-palette results.
- reanimated, Lottie, sprite sheets, expo-three/real-time 3D, Unity/Godot, because native rebuilds, no recolouring, asset explosion; parked, not dead.
- Full-size 1024 renders everywhere, because bitmap memory on mid-range Android.
- Auto-reload on OTA, geofencing for auto-finish, music during walks, extras over Celebration/walk screens, because they interrupt walks or add native deps.
**Risks:** low-end Android jank (drop weight shift and ear flick first); AI-asset style drift (locked style sentence + reference image in `assets/art/README.md`); iOS `capInsets` vs Android stretch; icon/splash need native rebuild.
